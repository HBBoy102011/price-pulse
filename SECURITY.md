# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
| --- | --- |
| 1.x | ✅ активная |
| < 1.0 | ❌ не поддерживается |

## Как сообщить об уязвимости

Пожалуйста, **не создавайте публичный issue** для проблем безопасности.

Используйте приватный канал GitHub:

1. Откройте [Security Advisories](https://github.com/HBBoy102011/price-pulse/security/advisories/new).
2. Опишите проблему, шаги воспроизведения и потенциальное влияние.
3. Приложите версию, конфигурацию (без секретов) и, если возможно, PoC.

Мы постараемся подтвердить получение в течение 3 рабочих дней и согласовать
сроки исправления. После релиза исправления информация раскрывается в advisory.

## Что считается уязвимостью

- обход ограничений доступа к боту (`TELEGRAM_ALLOWED_USER_IDS`);
- SSRF через парсеры или предпросмотр ссылки;
- SQL-инъекции, XSS, подделка запросов;
- утечка токенов, паролей БД или персональных данных;
- выполнение произвольного кода через загруженные файлы;
- отказ в обслуживании, вызванный одним запросом.

## Меры в проекте

- Секреты читаются только из переменных окружения / `.env`, файл исключён из Git.
- Парсеры соблюдают `robots.txt`, используют таймауты и честный User-Agent.
- Внешние ответы ограничены по размеру и обрабатываются как недоверенные данные.
- Бот проверяет `TELEGRAM_ALLOWED_USER_IDS` до выполнения команд.
- Деньги хранятся в `Numeric`, входные данные валидируются Pydantic.
- Зависимости можно проверить через `pip-audit` (см. README).

## Безопасный деплой

- Смените пароль PostgreSQL и `SECRET_KEY`-подобные значения.
- Не включайте `AUTO_CREATE_TABLES=true` в продакшене — используйте Alembic.
- Ограничьте CORS конкретным доменом вместо `*`.
- Включайте `TELEGRAM_BOT_POLLING` только на одном инстансе.
- Для публичного демо не храните реальные ссылки и персональные данные.
